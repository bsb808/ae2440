To Discuss

  • Clean workspace, again. The two R1 failures were both in span_statistics.m: one loaded the data from an absolute path on the student’s own machine (C:\Users\...\ansur_span.mat), the other never called load and relied on span already being in the workspace (its total_sum is also never initialized, so it would have failed anyway). Relative file names and clear + Run before saving catch both.
  • Building a sequence versus evaluating a formula. About 9 of 26 bounce.m compute h0*r^i inside the loop instead of the recursion h = r*h. The numbers come out right, but the point of the exercise (each step built from the previous one) is lost.
  • fprintf and using other AI suggestions:
%% Display the final results
fprintf('--- Calculated Statistics ---\n');
fprintf('Total Observations (n): %d\n', n_elements);
fprintf('Calculated Mean (μ):    %.4f meters\n', calculated_mean);
fprintf('Standard Deviation (σ):  %.4f meters\n', calculated_std);

Good patterns to show

  • Vector arithmetic in lcs_flow.m: all 26 evaluated x as a vector with array arithmetic ./ and .^; nobody looped over x or pasted the formula once per time.
  • Checking a loop against the built-ins (span_statistics.m), as six students did.
  • A legend that stays in step with the loop (lcs_flow.m): plot(x, v, 'DisplayName', sprintf('t = %d s', t)), then legend. Class demo of both legend methods, and how the classic one mislabels silently: lesson_legends.m.
